# 基准测试

## 已验证的事实（2026-11-09，macOS，DSH NEXT 2.0.22 / `@deepseek-ai/dsh 0.2.2-rc.1`）

1. **插件被客户端模块系统装载**
   在测试 profile 上启动 `dsh web`，页面 `__DSH_BOOT__` 的应用批次里包含
   `dsh-session-cache/client.js`（bundle 200，2.6 MB 合并批次），页面正常渲染。

2. **运行期生效**
   浏览器控制台：

   ```js
   typeof window.__DSH_SESSION_CACHE_STATS__   // "function"
   __DSH_SESSION_CACHE_STATS__()               // { kept: 1, max: 3, idleMs: 600000, ids: ["session-bfd..."] }
   ```

   打开第二个会话后再查：`__DSH_SESSION_CACHE_STATS__().ids.length === 2`，
   说明两个会话都被保留（未触发 LRU 淘汰，上限 3）。

3. **单个会话历史的量级**（本机真实日志）

   | 指标 | 数值 |
   | --- | --- |
   | `session.jsonl.zstd` 磁盘占用 | 7,532,258 B |
   | 解压后 JSONL | 16,228,430 B |

   冷启动一次要按页拉取投影后的历史；靠缓存切回时这部分不再重传。

## 尚未量化（需要弱网环境）

端到端的「切回耗时」没有在限速链路上做对照实验，原因是本机无法方便地复现稳定弱网 +
自动化点击会话并计时。建议的测量方法：

1. 用浏览器 DevTools 把网络限速到 `Slow 3G`（或 `tc` 限速）；
2. 关闭插件（patch 里 `disabled: true`）作为基线，记录 A → B → A 三次切换的
   「历史出现可交互」时间（Performance 面板或手动秒表，重复 5 次取中位数）；
3. 启用插件后重复同一序列；
4. 对照 `__DSH_SESSION_CACHE_STATS__()` 确认第二次 A 仍在 kept 列表里。

预期收益随切回频率与历史大小线性放大：历史越大、切回越快，省下的重传越多；
当会话只有几十条消息时，收益不可感知。

## 资源占用

- 每个保活会话：已加载的历史页（内存中的行投影）+ 一条跟随流；
- 上限：3 个会话、空闲 10 分钟自动释放；
- 关闭标签页 / 刷新页面时跟随流自动断开，插件随页面销毁。
